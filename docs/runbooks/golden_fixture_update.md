# Runbook: Golden Fixture Update

> **Status:** Draft  
> **Last updated:** 2026-03-01  
> **Applies to:** All files under `tests/fixtures/`

---

## 1. Purpose

Golden fixtures are the **authoritative expected outputs** for the MIRR
compiler pipeline. They are generated by the Rust reference implementation and
used by parity tests, schema tests, and stage-2 self-hosting validation.

Updating a golden fixture is a controlled operation because it changes the
definition of "correct" for the entire project.

## 2. When a Golden Fixture Update Is Required

- An **intentional** change to the Rust pipeline produces different output.
- A new test program is added and needs a corresponding fixture.
- An IR contract version bump changes the output schema.

## 3. When a Golden Fixture Update Is NOT the Answer

- A MIRR-CORE pipeline bug produces wrong output → fix the MIRR-CORE code.
- A non-determinism issue → escalate per `parity_triage.md §6`.
- Cosmetic formatting change → ensure both pipelines use identical
  serialization settings before touching fixtures.

## 4. Update Procedure

### Step 1 — Verify the Rust pipeline change is correct

```bash
# Run the full test suite to confirm no regressions
cargo test

# Run the self-hosting pipeline
cargo run -- --selfhost-compile examples/neonatal_respirator.mirr
```

All existing tests (except the fixture parity test you're about to update)
should pass. If other tests fail, fix those first.

### Step 2 — Generate new fixture output

```bash
# AST fixture
cargo run -- examples/neonatal_respirator.mirr --emit-json > tests/fixtures/ast/neonatal_respirator_ast.json

# Parse fixture
cargo run -- examples/neonatal_respirator.mirr --emit-parse-json > tests/fixtures/parse/neonatal_respirator_parsed.json

# Netlist fixture
cargo run -- --selfhost-compile --selfhost-compile-json examples/neonatal_respirator.mirr > tests/fixtures/netlist/neonatal_respirator.json
```

Adjust commands as needed for the specific fixture being updated.

### Step 3 — Diff old vs new

```bash
git diff tests/fixtures/
```

Review every changed field. Ask:
- Is this change expected from the Rust pipeline change?
- Are there unexpected side effects (e.g., field reordering, new fields)?
- Does the output still conform to the schema?

### Step 4 — Validate against schema

```bash
cargo test --test self_hosting_ir_schema_tests
```

If schema tests fail, the IR contract may need a version bump (requires ADR).

### Step 5 — Run full parity suite

```bash
cargo test --test self_hosting_parity_tests
cargo test --test temporal_lowering_tests
cargo test --test temporal_emit_tests
```

All parity tests must pass with the new fixtures.

### Step 6 — Document in PR

The PR that updates golden fixtures **must** include:

- [ ] **Rationale:** Why the fixture changed (link to the Rust pipeline change).
- [ ] **Diff summary:** What fields changed and why.
- [ ] **Schema impact:** Whether the IR contract version changed (if yes, link ADR).
- [ ] **Test results:** All parity and schema tests passing.

### Step 7 — Review and merge

Golden fixture updates require **explicit reviewer approval**. The reviewer
must verify:

- The Rust pipeline change is correct.
- The fixture diff matches the expected change.
- No unintended fields were added or removed.
- All tests pass.

## 5. Adding a New Fixture

When adding a new test program (e.g., a shift-register guard example):

1. Create the `.mirr` source file in `examples/`.
2. Generate all fixture files using the Rust pipeline (AST, parse, netlist).
3. Place fixtures in the appropriate `tests/fixtures/` subdirectory.
4. Add corresponding test cases that reference the new fixture.
5. Update `docs/testing/fixture_matrix.md` with the new fixture entry.
6. Update `docs/INDEX.md` if new documentation was created.

## 6. Fixture Directory Structure

```
tests/fixtures/
├── ast/                    # Parsed AST JSON (Level 1 IR)
├── netlist/                # Temporal netlist JSON (Level 3 IR)
├── parse/                  # Parser output JSON
├── semantic/               # Semantic validation output
└── tokens/                 # Lexer token stream output
```

## 7. Emergency Rollback

If a golden fixture update is merged and subsequently found to be incorrect:

1. `git revert` the fixture update commit.
2. File an issue explaining the incorrect update.
3. Re-run the triage process from `parity_triage.md`.
