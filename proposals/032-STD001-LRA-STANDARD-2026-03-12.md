## Motivation

LRA-001 and LRA-002 delivered the MIRR interactive paper: a single-page HTML
artifact with a WASM compiler playground, benchmark demos, and 14 academic
references.  The format works.  But the MIRR paper is welded to 26,990 lines of
Rust and 1,077 lines of Rocq proofs.  Other researchers cannot adopt the format
without inheriting the entire MIRR codebase.

**This campaign extracts the Living Research Artifact format into a reusable
GitHub Template Repository** — a clean HTML/CSS/JS scaffold that any researcher
can fork, fill with their own content, plug in their own WASM module, and deploy
to GitHub Pages in minutes.  We also write the formal **LRA-1.0 Specification**
defining what a conforming artifact must contain, add compliance tiers
(Bronze/Silver/Gold), and production-polish the MIRR paper itself to serve as
the reference implementation.

The deliverables:

1. **`template/`** staging directory (13 new files) — ready to push to a
   separate GitHub repo and enable "Template Repository" in settings.
2. **LRA-1.0 Specification** — formal definition of the standard.
3. **Production polish** on the MIRR paper (OG tags, accessibility, CSS
   generalization, keyboard shortcuts).
4. **Integration** — MIRR paper links to the template; README updated.

**The ultimate flex:** the bottom of the MIRR paper says _"The interactive
format of this paper is available as a reusable template"_ with a link.
You are not just publishing a paper — you are open-sourcing a new standard for
how systems research should be published.

## Section H: LRA-1.0 Specification — `template/spec/LRA-1.0.md` (NEW, ~200 lines)

The formal specification of the Living Research Artifact standard.

### Structure:

```markdown
# Living Research Artifact Specification v1.0

## 1. Purpose

A Living Research Artifact (LRA) is a self-contained, browser-readable
research paper that bundles executable evidence alongside its claims.

## 2. Definitions

- **Claim**: A numbered, verifiable assertion made by the paper.
- **Evidence**: An interactive section that demonstrates a claim.
- **Artifact**: The complete package: HTML + CSS + JS + optional WASM.

## 3. Required Sections

Every conforming LRA MUST contain:
- Abstract
- Claims (numbered, with evidence links)
- At least one body section
- Limitations
- References
- How to Cite (with BibTeX)

Every conforming LRA SHOULD contain:
- At least one Demo section linked to a claim
- A noscript fallback

## 4. Required Metadata

- <html lang="...">
- <meta name="description">
- Open Graph tags (og:title, og:description, og:type)
- CITATION.cff in the repository root

## 5. License

Every conforming LRA MUST be licensed under GPL-3.0 or later.
This ensures the artifact can never be paywalled and derivative
works (including template forks) inherit the copyleft obligation.

## 6. Compliance Tiers

### 6.1 Bronze — Static
- All Required Sections present
- GPL-3.0 license
- No JavaScript required for body text

### 6.2 Silver — Interactive
- Bronze requirements
- At least one Demo section with interactive controls
- noscript fallback

### 6.3 Gold — Executable
- Silver requirements
- WASM module loaded and functional
- At least one claim verifiable by executing tool in-browser
- Zero external dependencies (no CDN, no API calls)

## 7. Non-Requirements

- No specific CSS framework
- No specific WASM toolchain
- No specific programming language
- No minimum paper length

## 8. Versioning

This specification uses semantic versioning. Breaking changes
increment the major version. This is v1.0.
```

## Section I: Template CI — `template/.github/workflows/pages.yml` (NEW, ~50 lines)

GitHub Actions workflow that deploys the paper to GitHub Pages on push to main.

```yaml
name: Deploy LRA to GitHub Pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - name: Validate HTML
        run: |
          # Basic structure checks
          grep -q '<section id="abstract">' index.html
          grep -q '<section id="claims">' index.html
          grep -q '<section id="references">' index.html
          grep -q 'GPL-3.0' index.html
          echo "LRA structure validation passed"
      - uses: actions/configure-pages@v4
      - uses: actions/upload-pages-artifact@v3
        with:
          path: '.'
      - id: deployment
        uses: actions/deploy-pages@v4
```
