# TYPE-003 — Signed-Aware Width Inference

**Proposal #:** 004
**Campaign ID:** TYPE-003
**Date:** 2026-03-08
**Status:** SIGNED — EXECUTED (795 tests, 0 clippy warnings)
**Scope:** Campaign (9 files edited, 1 new file)

## Summary

Bridge the type checker and width inference subsystems so that signedness
propagates through width analysis. Before TYPE-003, the type checker
(`src/typeck/mod.rs`) computed a full `HashMap<*const Expr, SignalType>` for
every expression — then discarded it entirely. The width system re-walked every
expression from scratch, erasing signedness at every point by collapsing
`Signed(w)` and `Unsigned(w)` to bare `u32`.

TYPE-003:
1. Makes `typecheck_module` return a `TypeMap` that the pipeline threads to downstream passes.
2. Adds a `signed: bool` flag to `FlatNode::Signal` and `FlatNode::Prev`.
3. Fixes the negate constraint from `SameAs` (known incorrect) to `SameAsPlusOne` for unsigned operands.
4. Makes subtraction underflow diagnostics sign-aware (suppressed for signed operands).
5. Makes `Width` rendering sign-aware (`i16` vs `u16`) via `display_with_sign`.
6. Deduplicates `min_bits_for` (one canonical copy in `width::types`, typeck delegates).
7. Makes truncation and verify diagnostics say "signed" or "unsigned".

## Design Decisions

- D1: `TypeMap` is `HashMap<*const Expr, SignalType>` — pointer-keyed, O(1) lookup.
- D2: `FlatNode::Signal` and `FlatNode::Prev` carry `signed: bool` from declarations.
- D3: Negate constraint: unsigned N → `SameAsPlusOne` (N+1 bits), signed N → `SameAs` (N bits).
- D4: Subtraction underflow diagnostic suppressed only when both operands are signed.
- D5: `Width::Display` remains `u{}` for backward compat; `display_with_sign` is opt-in.
- D6: No new error codes — E505 and E511 messages enhanced with sign qualifier.
