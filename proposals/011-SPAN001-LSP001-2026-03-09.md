## Motivation

The MIRR compiler has zero source-position tracking. Tokens, AST nodes, and errors carry no line numbers, column offsets, or spans. This makes it impossible to build editor integration — every diagnostic would point to line 0, column 0.

An LSP (Language Server Protocol) server would give every editor (VS Code, Neovim, Emacs, Helix) real-time compiler diagnostics as the developer types. Instead of building editor-specific plugins, one LSP server serves them all — the same pattern used by rust-analyzer, clangd, and gopls.

**Current state:** No span tracking anywhere. No LSP server. VS Code extension at `vscode-mirr/` provides only TextMate syntax highlighting (no intelligence).

**Target state:** Span-annotated AST and errors. A working `mirr-lsp` binary that publishes diagnostics. Any LSP-compatible editor gets red squiggles on MIRR errors.

**Future campaigns (not in this proposal):**
- LSP-002: Go-to-definition, hover, completions, document symbols
- VSCODE-001: Upgrade `vscode-mirr/` with LSP client + grammar fixes

## Proposal

### Section A: Span Type — `src/span.rs` (new, ~45 lines)

New source-position type used throughout the compiler:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
pub struct Span {
    pub start_line: u32,  // 0-based (matches LSP protocol)
    pub start_col: u32,   // 0-based
    pub end_line: u32,     // 0-based
    pub end_col: u32,      // 0-based, exclusive
}
```

Methods: `single_line()`, `full_line()`, `multi_line()`, `merge()`.

16 bytes, `Copy` trait, zero-cost to pass around.

### Section B: Error Type Enhancement — `src/error.rs` (edit, 70 -> ~115 lines)

1. Add `span: Option<Span>` to all 6 `MirrError` variants
2. Add `pub fn with_span(self, span: Option<Span>) -> Self` builder
3. Add `pub fn span(&self) -> Option<Span>` accessor
4. Update `Display` to append ` (line N)` when span is `Some` (1-based for humans)
5. Fix B1: standardize error code prefixing in Display

### Section C: AST Span Annotations — `src/ast/program.rs`, `property.rs`, `pattern.rs` (edit)

Add `#[serde(default, skip_serializing_if = "Option::is_none")] pub span: Option<Span>` to:

| Struct | File |
|--------|------|
| `SignalDecl` | `src/ast/program.rs` |
| `Guard` | `src/ast/program.rs` |
| `Assignment` | `src/ast/program.rs` |
| `Reflex` | `src/ast/program.rs` |
| `Module` | `src/ast/program.rs` |
| `PropertyDecl` | `src/ast/property.rs` |
| `PatternDef` | `src/ast/pattern.rs` |
| `PatternCall` | `src/ast/pattern.rs` |

`Expr` deferred to LSP-002 (requires expression-level column tracking).

### Section D: Mechanical `span: None` Addition — 11 files, ~48 sites

Every `MirrError::*Error { message: ... }` gains `, span: None`.
Every AST struct construction gains `, span: None`.

Files: `module_parser.rs`, `expr_parser.rs`, `pattern_parser.rs`, `semantic.rs`, `typeck/mod.rs`, `expand/mod.rs`, `temporal/compiler.rs`, `temporal/emit.rs`, `temporal/low_level_ir.rs`, `emit/rspu.rs`, `emit/rspu_regalloc.rs`.

### Section E: Parser Span Capture — `src/parser/module_parser.rs` (edit, +~56 lines)

Upgrade `span: None` to actual spans using the already-available line index:

- `parse_signal()` gains `line_index: usize` parameter → `span: Some(Span::full_line(line_index as u32))`
- `parse_guard()` captures `start_line = *index` before parsing, `end_line = *index - 1` after closing brace → `span: Some(Span::multi_line(start, end))`
- Same pattern for `parse_reflex()`, `parse_property()`
- Error construction sites gain `span: Some(Span::full_line(*index as u32))`
- Expression parser errors wrapped by caller: `.map_err(|e| e.with_span(...))`

### Section F: Validation/Typeck Span Propagation — `semantic.rs`, `typeck/mod.rs` (edit)

Read `.span` from AST nodes when constructing errors:

```rust
// Before:
MirrError::SemanticError { message: format!("[E201] ...") }
// After:
MirrError::SemanticError { message: format!("[E201] ..."), span: sig.span }
```

~15 sites in semantic.rs, ~10 sites in typeck/mod.rs.

### Section G: LSP Server — 5 new files + Cargo.toml edit

> **Presidential veto applied:** `tower-lsp` and `tokio` were vetoed. The LSP server is implemented as a synchronous stdin/stdout JSON-RPC loop using `serde_json` (already a dependency). Zero new dependencies. This is consistent with MIRR's identity: `#![forbid(unsafe_code)]`, NASA P10 compliance, minimal dependency footprint.

**`Cargo.toml` changes:**
```toml
[[bin]]
name = "mirr-lsp"
path = "src/bin/mirr-lsp.rs"
```

No feature gates. No optional dependencies. The LSP binary is always buildable.

**New files:**

| File | Lines | Purpose |
|------|-------|---------|
| `src/bin/mirr-lsp.rs` | ~15 | Binary entry point — locks stdin/stdout, calls `lsp::server::run()` |
| `src/lsp/mod.rs` | ~5 | Module definition |
| `src/lsp/transport.rs` | ~65 | Content-Length framed JSON-RPC read/write over `BufRead`/`Write` |
| `src/lsp/server.rs` | ~290 | Synchronous LSP server loop — initialize, didOpen/Change/Save/Close, shutdown, exit |
| `src/lsp/diagnostics.rs` | ~130 | `MirrError` → LSP Diagnostic conversion with span mapping |

**LSP capabilities (this campaign):**
- `textDocument/didOpen` — compile + publish diagnostics
- `textDocument/didChange` — recompile + publish diagnostics (full sync)
- `textDocument/didSave` — full pipeline + publish diagnostics
- `textDocument/didClose` — clear diagnostics

**Bounded:** `MAX_SOURCE_BYTES = 1_048_576` — refuse to process files > 1MB.

**Pipeline config for LSP:** `{ typecheck: true, simplify: false, width: true, temporal: false, rspu: false }` — fast feedback over full compilation.
