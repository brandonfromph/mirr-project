## TYPE-005 — Higher-Order Patterns

### Summary

Extend the pattern system to accept **patterns as parameters** — enabling
compile-time composition of hardware templates. A pattern like `compose(inner, s, out)`
can invoke `inner(s, out)` during expansion, allowing reusable monitor/controller
pipelines to be assembled from smaller building blocks.

Scope is conservative: **Dimensions 1-2 only** (pattern-as-argument +
recursive sub-expansion). No generic type parameters. No conditional expansion.
The existing `MAX_EXPANSION_DEPTH=4` infrastructure is activated for real.

### Philosophy Gate

- **Generative power of three.** Parameter kinds become a triad: `Signal`, `Constant`, `Pattern`. No new language constructs. Signal/Guard/Reflex unchanged. PASS.
- **NASA P10.** Recursive expansion bounded by `MAX_EXPANSION_DEPTH=4` (explicit depth counter already threaded). Static cycle detection added (bounded DFS on ≤64 nodes). PASS.
- **Hardware-synthesizable.** Patterns are compile-time macros; hardware sees only the flat expanded module. PASS.
- **Properties don't affect hardware.** Properties within composed patterns remain SVA-only. PASS.

### Error Codes

| Code | Message pattern |
|------|----------------|
| E401 | `[E401] Pattern '{name}' parameter '{param}' has kind 'pattern' but argument is not a pattern reference.` |
| E402 | `[E402] Circular pattern reference detected: {cycle_path}.` |
| E403 | `[E403] Pattern '{name}' received pattern argument '{arg}' but no pattern '{arg}' is defined.` |

## RSPU-001 — R-SPU Instruction Emission

### Summary

Add a fifth emit backend that produces R-SPU (Reflex Signal Processing Unit)
assembly — a safety-critical instruction-level target. The R-SPU ISA is a
three-tier instruction set mapping 1:1 to MIRR's three primitives:

| MIRR Primitive | R-SPU Tier | Instructions |
|---------------|-----------|-------------|
| Signal | Register operations | `LOAD_INPUT`, `STORE_OUTPUT`, `MOV`, `LOAD_IMM` |
| Guard | Temporal accelerators | `SR_INIT`, `SR_TICK`, `SR_QUERY`, `CTR_INIT`, `CTR_TICK`, `CTR_QUERY`, `GUARD_AND`, `GUARD_OR` |
| Reflex | Conditional execution | `REFLEX_IF`, `PREV` |

Plus an ALU tier for expression evaluation (16 arithmetic/logic instructions
from `BinaryOp`/`UnaryOp`) and a safety tier for MAPE-K actions
(`SET_SIGNAL`, `SWITCH_MODE`, `EMERGENCY_STOP`).

### Philosophy Gate

- **Generative power of three.** R-SPU ISA is organized into three tiers (Register/Temporal/Reflex) mapping to three primitives. ALU and Safety are instruction-level support, not new constructs. PASS.
- **NASA P10.** Emitter uses bounded expression walk (`MAX_EXPR_NODES=512`). Register allocator is a single bounded pass over signals. No graph coloring — linear scan on partitioned register file. PASS.
- **Hardware-synthesizable.** R-SPU instructions *are* the synthesized hardware control. Each instruction has a defined single-cycle or bounded-cycle execution model. PASS.
- **Properties don't affect hardware.** Properties emit as R-SPU LTL Assertion Layer instructions (verification registers only, no datapath). PASS.

### Error Codes

| Code | Message pattern |
|------|----------------|
| E701 | `[E701] R-SPU register allocation failed: too many signals ({count} > {max}).` |
| E702 | `[E702] R-SPU instruction budget exceeded: {count} instructions > {max}.` |
| E703 | `[E703] R-SPU guard resource exhausted: {count} {kind} > {max}.` |

### Section H: R-SPU ISA — `src/emit/rspu_isa.rs` (new)

R-SPU instruction set definition:

```rust
pub enum RspuInstruction {
    // Register tier
    LoadInput   { dst: RegId, port: PortId },
    StoreOutput { src: RegId, port: PortId },
    Mov         { dst: RegId, src: RegId },
    LoadImm     { dst: RegId, value: u64, width: u32 },

    // ALU tier (16 ops from BinaryOp/UnaryOp)
    Alu         { op: AluOp, dst: RegId, a: RegId, b: RegId },
    AluImm      { op: AluOp, dst: RegId, a: RegId, imm: u64 },
    AluUnary    { op: AluUnaryOp, dst: RegId, src: RegId },

    // Temporal tier
    SrInit      { guard: GuardId, length: u32, cond: RegId },
    SrTick      { guard: GuardId },
    SrQuery     { dst: RegId, guard: GuardId },
    CtrInit     { guard: GuardId, target: u64, cond: RegId },
    CtrTick     { guard: GuardId },
    CtrQuery    { dst: RegId, guard: GuardId },
    GuardAnd    { dst: GuardId, a: GuardId, b: GuardId },
    GuardOr     { dst: GuardId, a: GuardId, b: GuardId },

    // Reflex tier
    ReflexIf    { guard: GuardId, dst: RegId, src: RegId },
    Prev        { dst: RegId, signal: RegId, delay: u32 },

    // Safety tier (MAPE-K actions)
    EmergencyStop,

    // LTL Assertion tier (verification only)
    AssertAlways { cond: RegId, property_id: u32 },
    AssertNever  { cond: RegId, property_id: u32 },
}
```

Resource limits (matching NASA P10 bounded-resource model):
```rust
pub const MAX_REGISTERS: usize = 256;
pub const MAX_GUARDS: usize = 64;
pub const MAX_INSTRUCTIONS: usize = 4096;
```

### Section I: Register Allocator — `src/emit/rspu_regalloc.rs` (new)

Linear-scan register allocation partitioned by signal kind:

| Partition | Range | Maps to |
|-----------|-------|---------|
| Input ports | R0-R63 | `SignalKind::Input` signals |
| Output ports | R64-R127 | `SignalKind::Output` signals |
| Internals | R128-R191 | `SignalKind::Internal` signals |
| Temporaries | R192-R255 | Expression evaluation intermediates |

Single bounded pass over `module.signals` → `HashMap<String, RegId>`.
No graph coloring. `O(n)` where `n ≤ MAX_REGISTERS`.

### Section J: R-SPU Emitter — `src/emit/rspu.rs` (new)

Follows the same pattern as all four existing backends:

1. Accept `&PipelineResult`
2. Allocate registers for all signals
3. Walk `TemporalNetlist.guards` → emit `SR_INIT`/`CTR_INIT` + tick/query sequences
4. Walk `module.reflexes` → emit `REFLEX_IF` with expression evaluation preambles
5. Walk `module.properties` → emit `AssertAlways`/`AssertNever` (verification tier)
6. Emit `LOAD_INPUT` preamble and `STORE_OUTPUT` postamble per tick
7. Return either text assembly or structured `RspuProgram`
