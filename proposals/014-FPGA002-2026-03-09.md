## Motivation

The MIRR compiler supports `BinaryOp::Mul` end-to-end — parser, type checker, width inference, simplifier, and all emitters. However, the Verilog emitter produces bare `(a * b)` expressions with **no synthesis attributes**, meaning FPGA synthesis tools must guess whether to map multiplications to fabric logic or dedicated DSP blocks.

For small multiplies (u8 * u8) this is fine — fabric logic suffices. But for production signal processing (u16 * u16 = 32-bit result), unmapped multiplies consume massive LUT resources and fail timing. Every real FPGA design either:

1. Adds `(* use_dsp = "yes" *)` annotations (Xilinx/Yosys)
2. Instantiates vendor DSP primitives directly (Intel `cyclonev_mac`, Lattice `SB_MAC16`)
3. Uses vendor IP catalog wrappers

MIRR currently does none of these. A sensor fusion controller with even one multiply-accumulate loop will fail timing on any Artix-7 without manual intervention.

**Current state:** `(a * b)` emits as raw `*` operator — synthesis tool guesses DSP mapping.

**Target state:** Multiplications above a configurable width threshold automatically emit with `(* use_dsp48 = "yes" *)` (Xilinx) or equivalent vendor attributes. The `--dsp-threshold N` flag controls the cutoff. A new analysis pass detects multiply patterns and reports DSP utilization.

**Not in scope — BRAM inference:** Block RAM requires `SignalType::Array` in the AST, array indexing in `Expr`, parser changes, type checker changes, width inference changes, and new emitter patterns. This is a language-level change (campaign ARRAY-001) that must be designed separately. FPGA-002 is emitter-only.

### Section B: FpgaTarget DSP Metadata — `src/emit/fpga_target.rs` (edit, +20 lines)

Add DSP primitive info to each target:

```rust
impl FpgaTarget {
    pub fn dsp_primitive(&self) -> &'static str {
        match self {
            Self::Generic => "dsp",
            Self::Xilinx7 => "DSP48E1",
            Self::XilinxUS => "DSP48E2",
            Self::IntelCyclone => "cyclonev_mac",
            Self::LatticeIce40 => "SB_MAC16",
        }
    }

    pub fn dsp_attribute(&self) -> &'static str {
        match self {
            Self::Generic => "(* use_dsp = \"yes\" *)",
            Self::Xilinx7 | Self::XilinxUS => "(* use_dsp48 = \"yes\" *)",
            Self::IntelCyclone => "(* multstyle = \"dsp\" *)",
            Self::LatticeIce40 => "(* use_dsp = \"yes\" *)",
        }
    }

    pub fn dsp_max_input_width(&self) -> u32 {
        match self {
            Self::Generic => 18,
            Self::Xilinx7 => 25,       // DSP48E1: 25x18
            Self::XilinxUS => 27,       // DSP48E2: 27x18
            Self::IntelCyclone => 27,   // 27x27 variable-precision
            Self::LatticeIce40 => 16,   // SB_MAC16: 16x16
        }
    }
}
```

### Section C: Verilog DSP Attribute Emission — `src/emit/verilog.rs` (edit, +30 lines)

In `emit_reflex_logic()`, before the `always_comb begin` block, check if the reflex contains a multiply expression with operands above threshold. If so, emit the vendor-specific DSP attribute:

```systemverilog
  (* use_dsp48 = "yes" *)
  always_comb begin
    voted_value = '0;
    if (a_healthy_out) voted_value = (sensor_a * calibration_factor);
  end
```

The attribute is placed on the `always_comb` statement — this is the standard Xilinx/Yosys placement.

### Section D: CLI Flag — `src/bin/mirr-compile.rs` (edit, +10 lines)

Add `--dsp-threshold N` flag (default: 9). When N=0, disable DSP attribute emission.

### Section E: DSP Example — new `examples/fir_filter.mirr` (~40 lines)

A 4-tap FIR filter demonstrating multiply-accumulate:

```mirr
module fir_filter {
    signal sample_in:  in u16;
    signal coeff_0:    in u16;
    signal coeff_1:    in u16;
    signal coeff_2:    in u16;
    signal coeff_3:    in u16;
    signal filter_out: out u32;
    signal tap_0:      internal u32;

    guard new_sample {
        when sample_in > 0
        for 1 cycles;
    }

    reflex compute_tap0 {
        on new_sample {
            tap_0 = sample_in * coeff_0;
        }
    }

    reflex output_sum {
        on new_sample {
            filter_out = tap_0;
        }
    }
}
```
