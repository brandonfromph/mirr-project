## Motivation

The Rust compiler is considered the best compiler ever built not because of what it compiles but because of how it teaches. Every error tells you what's wrong, where exactly, why it happened, and how to fix it. Sometimes it writes the fix for you.

MIRR has 37 error codes across 100+ construction sites. Today, every error prints as a flat string:

```
[E100] Parse error: Guard name cannot be empty. (line 5)
```

No source snippet. No caret indicator. No `help:` text. No secondary spans. 96% of parse errors and 100% of width/temporal/R-SPU errors still have `span: None`. Error codes are inconsistent: SemanticError and TypeError Display arms omit the code prefix, RspuError produces double codes (`[E700] R-SPU error: [E701] ...`), E603 and E701 are overloaded across different failure modes, and E1xx/E3xx/E4xx each use a single generic code for dozens of distinct messages.

**Target state:** Every MIRR error looks like a rustc error:

```
error[E201]: duplicate signal name `temperature`
 --> neonatal.mirr:5:5
  |
5 |     signal temperature: in u16;
  |            ^^^^^^^^^^^ `temperature` is already declared
  |
note: first defined here
 --> neonatal.mirr:3:5
  |
3 |     signal temperature: in u8;
  |            ^^^^^^^^^^^
  = help: each signal name must be unique within a module
```

The VS Code extension (`vscode-mirr/`) gains an LSP client connecting to `mirr-lsp`, plus grammar fixes for missing keywords and signed types.

**Future campaigns (not in this proposal):**
- ERR-002: Error accumulation (multiple errors per compilation, not just first-error-stops)
- LSP-002: Go-to-definition, hover, completions, document symbols

## Proposal

### Section A: Diagnostic Renderer — `src/diagnostic.rs` (new, ~350 lines)

Central rendering engine. Zero dependencies beyond `std`.

```rust
#![forbid(unsafe_code)]

use crate::span::Span;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Severity { Error, Warning, Info, Help }

#[derive(Debug, Clone)]
pub struct Label {
    pub span: Option<Span>,
    pub message: String,
    pub kind: LabelKind,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum LabelKind { Note, Help }

#[derive(Debug, Clone)]
pub struct Diagnostic {
    pub severity: Severity,
    pub code: Option<String>,      // e.g. "E201"
    pub message: String,           // primary message
    pub span: Option<Span>,        // primary span
    pub labels: Vec<Label>,        // secondary (note:, help:)
}
```

**`render_to_string(diag, source, file_path) -> String`** — produces:
```
error[E201]: duplicate signal name `temperature`
 --> neonatal.mirr:5:5
  |
5 |     signal temperature: in u16;
  |            ^^^^^^^^^^^ `temperature` is already declared
  |
note: first defined here
 --> neonatal.mirr:3:5
  |
3 |     signal temperature: in u8;
  |            ^^^^^^^^^^^
  = help: each signal name must be unique within a module
```

**Bounded:** Line splitting uses `source.lines()` (iterator). Caret width capped at `MAX_DIAG_LINE_WIDTH = 200`. Labels capped at `MAX_LABELS = 8`.

### Section B: Suggest Module — `src/suggest.rs` (new, ~60 lines)

Levenshtein distance for "did you mean?" suggestions. Zero dependencies.

```rust
#![forbid(unsafe_code)]

const MAX_CANDIDATES: usize = 1024;
const MAX_EDIT_DISTANCE: usize = 3;

pub fn closest_match<'a>(name: &str, candidates: &[&'a str]) -> Option<&'a str> { ... }
fn levenshtein(a: &str, b: &str) -> usize { ... }
```

No recursion. O(n×m) where n,m are string lengths (max 64 for signal names).

Assign unique sub-codes to every parse error. Every error gains a help suggestion.

**New E1xx codes (module_parser.rs, ~25 sites):**

| Code | Message | Help |
|------|---------|------|

| E102 | Expected `module` declaration | `.mirr` files must start with `module name {` |
| E103 | Module name empty | add a name after `module` |
| E104 | Module not closed | add `}` before end of file |
| E105 | Unexpected line inside module | expected `signal`, `guard`, `reflex`, `property`, or `}` |
| E106 | Signal must end with `;` | format: `signal name: direction type;` |
| E107 | Signal missing `:` | format: `signal name: in/out/internal type;` |
| E108 | Signal name empty | add a signal name |
| E109 | Signal kind missing | expected `in`, `out`, or `internal` |
| E110 | Signal type missing | expected `bool`, `uN`, or `iN` |
| E111 | Unknown signal kind | expected `in`, `out`, or `internal` |
| E112 | Unknown signal type | expected `bool`, `uN`, or `iN` |
| E113 | Width exceeds maximum of 64 | maximum bit-width is 64 |
| E114 | Guard name empty | add a name after `guard` |
| E115 | Guard missing `when` clause | add `when <condition>` |
