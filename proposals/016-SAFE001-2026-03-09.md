## Motivation

The MIRR compiler enforces `#![forbid(unsafe_code)]` at the library crate root (`src/lib.rs:18`), which prohibits `unsafe` blocks throughout the entire library crate. A background agent performing technical debt cleanup partially removed redundant `#![forbid(unsafe_code)]` annotations from library submodules, leaving the codebase in an inconsistent state — some submodules have the attribute, some don't.

There are two categories of enforcement gap:

1. **Library submodules (48 files):** The crate-root attribute already covers these, but defense-in-depth means each module independently declares the constraint. If a future refactoring ever moves a module to a different crate (e.g., extracting `ast/` into `mirr-ast`), the local attribute ensures the safety constraint travels with the code. This is standard practice for DO-178C traceable components.

2. **Binary crates (4 files):** `src/bin/mirr-simplify.rs`, `src/bin/mirr-width.rs`, `src/bin/run_lexer.rs`, and `src/bin/generate_mirr_stress.rs` are **separate crate roots**. The library crate's `#![forbid(unsafe_code)]` does NOT cover them. These binaries currently have zero unsafe-code enforcement. This is a genuine safety gap, not merely defense-in-depth.

**Current state:** 21 of 73 `.rs` files have `#![forbid(unsafe_code)]`. 48 library submodules and 4 binary crates lack it.

**Target state:** All 73 `.rs` files carry `#![forbid(unsafe_code)]`. Every module and binary crate independently enforces the NASA Power-of-10 no-unsafe rule.
